# План
## 1. Базовый site: - что вообще проиндексировано
```bash
site:github.com "мой_username"
```
Поисковик нечего не выдал так как , у большого известного домена как (tryhackme.com) - тысячи проиндексированных страниц. У маленького личного профиля с малым трафиком - индекс может быть почти пустым, особенно если:
1. Аккаунт свежий/малоактивный
2. Мало внешних ссылок на профиль (никто не ссылается с других сайтов)
3. Репозиторий приватные или без активности (issues/PR/звезды создают "сигналы", которые ускоряют индексацию)

## 2. Теперь перейдем к собсвенному поиску GitGub, потому что он ищет прям в коде, а не полагается на индексацию Google
Зайдем на github.com, и введем в поиск:
```bash
user:"мой_user" password
```
И тут тоже пусто, когда мы натыкаемся на одну и ту же фундаментальную вещь в OSINT: "ничего не найденоЭ почти никогда не значит "там ничего нет" - почти всегда это значит "источник еще не проиндексировал/не увидел это.Для реальной цели это критично понимать: если dork ничего не дает, нужно пробовать другой источник, а не делать вывод что данных не существует.

## 3. Раз code search не индексирован, можно зайти в свой репозиторий и использовать посик внутри репозитория:
```bash
site:github.com/мой_user/cyber-security-notes "password"
```
Тут уже выдало это **This repository's code is being indexed right now. Try again in a few minutes.**, это значит что мы триггернули индексацию иммено этог репозитория, можно подождать и повторить еще раз.

# Сделаем индексацию  на крупном проекте , чтобы увидеть все наглядно:
## Вариант 1: GitHub Code Search на большом open-source проекте например facebook/react
```bash
repo:facebook/react patch:*.md "TODO"
repo:facebook/react "console.log"
```
И вывод пуст, Даже гигантский, суперпопулярный репозиторий вроде facebook/react не гарантированно доступен для полнотекстового Code Search в любой момент — это подтверждает наш более ранний вывод намного нагляднее: индексация — не универсальная константа, у GitHub Code Search есть свои пробелы и ограничения, независимо от размера/популярности цели

## Вариант 2: Google dork на крупном публичном домене (открытые директории)
```bash
intitle:"index of" site:mit.edu filetype:pdf
site:nasa.gov filetype:pdf "public"
```
В итоге можем увидеть много разных учебных материалов 

# Вывод
## Технический вывод про операторы:
- Операторы Google (site:, filetype:) работают только в самом Google — не переносятся на другие платформы
- GitHub Code Search использует свой синтаксис: user:, repo:, path:*.ext (не filename:/extension: — устаревший синтаксис)
- Поле "Go to file" ≠ полнотекстовый поиск, ищет только по имени файла
## Методологический вывод:
- Отсутствие результатов ≠ отсутствие данных — часто означает "источник ещё не проиндексировал"
- GitHub индексирует код лениво, по требованию — сам факт поиска может триггернуть индексацию
- Для реальной (не своей) цели: если dork пустой, нужно пробовать другой источник/подождать/зайти напрямую, а не считать вопрос закрытым

# Итог по теме
Это хороший пример разницы между "мусорной" целью (мой маленький Github) и "богатой" целью(nasa.gov) - операторы работают одинаково технически, но результат зависит от того, насколько ресурс вообще проиндексирован и насколько там есть,  что искать легально публично доступного
