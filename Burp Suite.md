# Proxy 
## Ядро всего Burp Suite. Работает как посредник между твоим браузером и целевым сайтом: браузер настраивается отправлять весь трафик через Burp (обычно 127.0.0.1:8000), Burp перехватывает каждый запрос до того, как он уйдёт на сервер, даёт возможность посмотреть и изменить его вручную, и только потом (или сразу, если Intercept выключен) отправляет дальше
Intercept on/off - ключевой переключатель: включен - каждый запрос виснет и ждет твоего действия; выключен - трафик просто логируется без остновки , ты смотришь его постфактум

# HTTP history
##  Вкладка внутри Proxy - полный лог всех запросов, прошедших через Burp, в хронологическом порядке. Каждую строку можно кликнуть и увидеть полный Request/Response

# Repeater
## Инструмент для ручного повторения и модификации одного конкретного запроса столько раз, сколько нужно
Отправляем запрос из HTTP history(правый клик -> "Send to Repeater"), дальше можешь менять любое поле(параметр, заголовок. метод) и жать "Send"
сново и сново, сразу видя изменившийся ответ рядом

Классический пример использования: нашел GET /profil?user_id=42 - меняешь 42 на 43 в Reapeater и смотришь, вернет ли сервер данные другого поьзователя (это уже путь к уязвимости IDOR )

# Intruder
## Автоматизированная версия Repeater — вместо ручного изменения одного значения, перебирает список значений по заданному месту в запросе

Например, для GET /login?username=admin&password=§FUZZ§ (место для подстановки помечается §...§) можно загрузить список из 10000 паролей, и Intruder отправит запрос 10000 раз, каждый раз подставляя новое значение — это основа брутфорса паролей/параметров через Burp

4 режима атаки:
1. Sniper (один параметр за раз)
2. Battering ram (одно значение во все позиции одновременно)
3. Pitchfork (несколько параметров параллельно из разных списков)
4. Cluster bomb (все комбинации нескольких параметров)

# Decoder
## Утилита кодирования/декодирования данных без похода на сторонние сайты — Base64, URL-encoding, HTML-entities, Hex и т.д., можно применять по цепочке (например, сначала декодировать URL-encoding, затем Base64)

Прямая связка с тем, что мы уже разбирали Base64 в Basic Auth(Authorization: Basic YWRtaW46...) и %3A в URL при поиске на GitHub?  
Вот иименно для расшифровки таких вещей и служит Decoder — не нужно бегать в консоль/онлайн-сервисы

# Comparer
## Сравнивает два ответа (или запроса) побайтово/построчно, подсвечивая разницу. Полезно, когда нужно понять, что именно изменилось между двумя похожими ответами — например, ответ сервера на валидный логин vs невалидный, чтобы найти едва заметное отличие (лишний пробел, разное время ответа, разный текст ошибки), которое можно использовать для определения, существует ли конкретный username в системе (username enumeration)

# Inspector
## Более новая панель (в современных версиях Burp), разбирающая запрос/ответ на составные, кликабельные части — заголовки, куки, параметры отдельными строками с возможностью быстро редактировать каждое поле, не копаясь в сыром тексте запроса руками. По сути — более удобный визуальный слой над тем же самым, что видно в Repeater/HTTP history в текстовом виде
