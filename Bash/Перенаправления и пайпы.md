# Перенаправления (>, >>, <, 2>, &>)
Что это - перенаправление меняет, откуда команда берёт данные или куда отправляет результат — вместо привычного экрана

---

# > — перезаписать файл выводом команды
```bash
echo "192.168.3.1" > hosts.txt

# если файл существовал - его содержимое полсностью стирается и заменяется новым
```

# >> — добавить в конец файла, не стирая старое
```bash
echo "192.168.3.109" >> hosts.txt

дописывает строку в конец файла, всё, что было раньше, остаётся нетронутым
```

# < — взять данные из файла как вход 
```bash
whiel read -r ip
do
    ...
done < "$file"
```

# 2> — перенаправить именно ошибки (не обычный вывод)
У каждой команды в bash есть два отдельных потока вывода:
1. stdout (стандартный вывод, номер 1) — обычный, "хороший" результат
2. stderr (стандартный вывод ошибок, номер 2) — сообщения об ошибках
```bash
ping -c1 999.999.999.999 2> errors.log

Тут именно ошибка уйдёт в errors.log, а не на экран, при этом обычный вывод остался бы виден в терминале
```

# > /dev/null и 2>&1 
```bash
ip=$1
ping -c1 "$ip" > /dev/null 2>&1

> /dev/null — прячет обычный вывод (stdout)
2>&1 — говорит "поток ошибок (2) отправляй туда же, куда сейчас идёт обычный вывод (1)" — то есть тоже в /dev/null
```
# &> — короткая запись для "спрятать вообще всё"
```bash
ping -c1 "$ip" &> /dev/null

Это то же самое, что > /dev/null 2>&1, просто более короткая современная форма записи
```
