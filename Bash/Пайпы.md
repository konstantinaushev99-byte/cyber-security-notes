###  как пайп работает "под капотом"
- Каждая команда в пайпе на самом деле запускается параллельно, а не строго по очереди "сначала первая полностью завершится, потом начнётся вторая". Данные текут потоком, как по трубе (отсюда и название "pipe" — труба) — как только первая команда произвела хоть немного вывода, вторая уже может начать его обрабатывать, не дожидаясь полного завершения первой

Это важно понимать для длительных процессов, например:
```bash
ping 192.168.3.109 | grep "time"

Тут grep начинает фильтровать строки сразу, по мере того как ping их выдаёт (а ping без -c работает бесконечно) — вывод появляется постепенно, а не одним куском в конце
```
$? после пайпа — частая ловушка
```bash
cat несуществующий_файл.txt | grep "test"
echo $?
```
Тут $? покажет код возврата последней команды в цепочке (grep), а не cat
Как проверить код возврата каждой команды в пайпе отдельно — через специальный массив PIPESTATUS:
```bash
cat несуществующий_файл.txt | grep "test"
echo "${PIPESTATUS[0]}"    # код возврата cat
echo "${PIPESTATUS[1]}"    # код возврата grep
```
# tee пайп, который одновременно показывает И сохраняет
```bash
ping -c3 192.168.3.109 | tee ping_result.txt

tee — как тройник в трубе: пропускает данные дальше (на экран) и одновременно копирует их в файл. Вы увидите результат сразу в терминале, и он же сохранится в ping_result.txt
```
# Пример кода с tee
```bash
check_host() {                         # функция
    ip=$1
    ping -c1 "$ip" > /dev/null
    if [ $? -eq 0 ]; then         # условие и код возврата
        echo "$ip - доступен"
        return 0
    else
        echo "$ip - недоступен"
        return 1
    fi
}

hosts_to_check=("192.168.3.109" "192.168.3.116" "8.8.8.8")   # массив

for ip in "${hosts_to_check[@]}"   # цикл for 
do
    check_host "$ip"
done | tee scan_log.txt  # вывод в терминал и сохранение в файл scan_log.txt
```
