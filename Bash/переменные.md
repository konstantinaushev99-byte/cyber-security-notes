# Переменные 
### Что это - это место, где мы можем хранить значение

---

# Например:
```bash
#!/bin/bash - говорит редактору писать код в bash

name="kosta" 
Теперь есть переменная name, внутри которой лежит текст kosta
Чтобы получить значение переменной, используется $: 
echo $name
Вывод: kosta
```

---

# Отличие от других языков 
1. В Bash нет пробелов вокруг '='
   ```bash
   ip="192.168.3.116" - правильно
   ip = "192.168.3.116" - неправильно
   ```
   Почему?
   Потому что Bash воспринимает это как команду:
   ```bash
   ip
   =
   192.168.3.116
   ```

target="192.168.3.116"

nmap 192.168.3.116

# Кавычки "$var" $var '$var'
```bash
name="Kosta Linux"

echo $name  # Kosta Linux - но это 2 отдельных слова для echo
echo "$name" # Kosta Linux - это ОДНО значение, безопасно
echo '$name' # $name - одинарные кавычки не подставляют переменную вообще!
```
Практический пример, где это реально ломается:
```bash
file="my file.txt"

touch $file # создаст 2 файла: "my" и "file.txt" — ОШИБКА
touch "$file" # создаст 1 файл: "my file.txt" — правильно
```

# Аргументы командной строки — $1, $2, $0, $#, $@
```bash
echo "Имя скрипта: $0"
echo "Первый аргумент: $1"
echo "Второй аргумент: $2"
echo "Всего аргументов: $#"

Пример:
ip=$1
port=$2
nmap -p $port $ip

Запуск ./scan.sh 192.168.3.109 22
```
Короткое правило:
- Порядок $1, $2 при запуске скрипта — решаете вы, когда пишете код скрипта
- Порядок флагов и их значений внутри самой команды (nmap -p 22 ...) — решают разработчики той программы, которую вы вызываете (в данном случае nmap), и вы просто следуете её синтаксису, как с любой другой командой (вспомните cut -d':' -f1 — там тоже сначала флаг, потом его значение, это просто стандарт большинства Linux-утилит)

# Арифметика с переменными
В Bash обычное '+' внутри переменной не работает как число — нужна особая конструкция:
```bash
count=5
count=$((count + 1))
echo $count    # 6

арифметическое расширение - $(( ... )), все что внутри bash воспринимает это как математическое выражение

переменную count можно заменить для любую другую переменную
```

# Локальные переменные vs переменные окружения (export)
1. Обычная переменная - видна только внутри того файла/сессии, где вы её создали
```bash
target="192.168.3.109"
```
2. Переменная окружения — видна и самому скрипту, и всем программам/скриптам, которые он запускает изнутри себя
```bash
export target="192.168.3.109"
```
3. Наглядный пример
```bash
#!/bin/bash
export target="192.168.3.109"  #Команда внутри файла parent.sh
./child.sh 

#!/bin/bash
echo "IP внутри child: $target"  #Команда внутри файла child.sh

./parent #Ввод команды в терминале Linux
Вывод: IP внутри child: 192.168.3.109
```

# $? — код возврата последней команды
После любой выполненной команды bash автоматически сохраняет число в специальную переменную $?:
- 0 — команда выполнилась успешно
- любое другое число (1, 2, 127 и т.д.) — команда завершилась с ошибкой
Пример 1:
```bash
ping -c1 192.168.3.109
echo $?

Если хост ответил — $? покажет 0
```
Пример 2:
```bash
ping -c1 192.168.3.109
echo "готово"
echo $?         # это уже код возврата echo "готово", а НЕ ping!


Важный нюанс — $? всегда хранит код только что выполненной команды, и обновляется после каждой новой команды. То есть если между ping и echo $? вставить ещё одну команду, $? уже покажет результат той, вставленной, а не пинга
```
