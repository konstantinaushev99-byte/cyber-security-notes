# Detecting SQL injection vulnerabilities
Вы можете обнаружить SQL-инъекции вручную, используя систематический набор тестов для каждой точки входа в приложение. Для этого обычно требуется отправить следующие данные:

- Используйте символ одинарной кавычки ```'``` и проверьте наличие ошибок или других аномалий
- Некоторый синтаксис, специфичный для SQL, который вычисляет базовое (исходное) значение точки входа, а также другое значение, и отслеживает систематические различия в ответах приложения
- Логические условия, такие как ```OR 1=1``` и ```OR 1=2```, позволяют выявить различия в ответах приложения
- Программы, предназначенные для запуска задержек при выполнении в рамках SQL-запроса, отслеживают различия во времени ответа
- OAST-пакеты предназначены для запуска внеполосного сетевого взаимодействия при выполнении в рамках SQL-запроса и мониторинга любых последующих взаимодействий

В качестве альтернативы, большинство уязвимостей SQL-инъекций можно быстро и надежно обнаружить с помощью Burp Scanner

## SQL injection in different parts of the query
Большинство уязвимостей SQL-инъекций возникают в WHERE блоке запроса SELECT. Большинство опытных тестировщиков знакомы с этим типом SQL-инъекций

Однако уязвимости SQL-инъекций могут возникать в любом месте запроса и в запросах разных типов. К другим распространенным местам возникновения SQL-инъекций относятся:

- В ```UPDATE``` заявлениях, в рамках обновленных значений или ```WHERE``` пункта
- В ```INSERT``` операторах, внутри вставляемых значений
- В ```SELECT``` операторах — внутри названия таблицы или столбца
- В ```SELECT``` утверждениях, внутри данного ```ORDER BY``` пункта

## SQL injection in different contexts
Мы можем выполнять атаки с использованием SQL-инъекций, используя любые управляемые входные данные, которые обрабатываются приложением как SQL-запрос. Например, некоторые веб-сайты принимают входные данные в формате JSON или XML и используют их для запроса к базе данных

Эти различные форматы могут предоставлять разные способы маскировки атак , которые блокируются WAF и другими механизмами защиты. Слабые реализации часто ищут распространенные ключевые слова SQL-инъекций в запросе, поэтому вы можете обойти эти фильтры, закодировав или экранировав символы в запрещенных ключевых словах. Например, следующая SQL-инъекция на основе XML использует последовательность экранирования XML для кодирования символа ```S``` в 
```SELECT```:
```
<stockCheck>
    <productId>123</productId>
    <storeId>999 &#x53;ELECT * FROM information_schema.tables</storeId>
</stockCheck>
```
Эти данные будут декодированы на стороне сервера, прежде чем будут переданы интерпретатору SQL
