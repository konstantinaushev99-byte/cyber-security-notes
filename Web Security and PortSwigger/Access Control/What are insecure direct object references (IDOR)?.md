## What are insecure direct object references (IDOR)?
Что это - это тип уязвимости контроля доступа, возникающий, когда приложение использует предоставленные пользователем входные данные для прямого доступа к объектам

### Примеры IDOR
#### Уязвимость IDOR, связанная с прямым обращением к объектам базы данных
1. Есть веб-сайт, который использует следующий URL-адрес для доступа к странице учетной записи клиента:
   ```https://insecure-website.com/customer_account?customer_number=132355```
   В данном случае номер клиента используется непосредственно в качестве индекса записи в запросах, выполняемых к серверной базе данных
   Если отсутствуют другие средства контроля, злоумышленник может просто изменить это customer_numberзначение, обойдя средства контроля доступа, и просмотреть записи других клиентов

### Уязвимость IDOR, связанная с прямой ссылкой на статические файлы
1. Уязвимости IDOR часто возникают, когда конфиденциальные ресурсы находятся в статических файлах на файловой системе сервера
   Например, веб-сайт может сохранять расшифровки сообщений чата на диск, используя увеличивающееся имя файла, и позволять пользователям получать к ним доступ, перейдя по URL-адресу, подобному следующему:
   ```https://insecure-website.com/static/12144.txt```
   В такой ситуации злоумышленник может просто изменить имя файла, чтобы получить доступ к расшифровке, созданной другим пользователем, и потенциально завладеть учетными данными пользователя и другой конфиденциальной информацией
