# Vulnerabilities in other authentication mechanisms(Уязвимости в других механизмах аутентификации)
Помимо обычного Login, уязвимости могут находиться в функциях Remember Me, Password Reset и Change Password
## 1. Remember Me
Функция Remember Me использует постоянный cookie-токен, который позволяет оставаться авторизованным
Уязвимость
Токен опасен, если он строится из предсказуемых данных:
- username
- timestamp
- password
- другие статические значения
Если злоумышленник поймет формулу генерации, он может пытаться подобрать токены других пользователей

Base64 - это кодирование, а не шифрование
Если используется хеш без salt, его также может быть возможно подобрать по словарю

## 2. Password Reset
Сброс пароля особенно важен, потому что пользователь не может подтвердить личность старым паролем
Небезопасный вариант - /reset-password?user=victim
Если сервер определяет аккаунт только по username, злоумышленник может изменить параметр и попытаться сбросить пароль другого пользователя
Безопасный вариант - /reset-password?token=<random_token> - Используется случайный high-entropy token:
Token должен:
- быть непредсказуемым
- быть связан с конкретным аккаунтом
- иметь короткий срок действия
- становиться недействительным после использования
### Password Reset Poisoning
Если reset URL формируется небезопасно, злоумышленник может попытаться получить токен сброса другого пользователя и использовать его для смены пароля

## 3. Отправка пароля по Email
Отправлять постоянный пароль по email — небезопасно
Причины:
- email не предназначен для хранения секретов
- сообщение может быть перехвачено или доступно на другом устройстве

## 4. Change Password
Обычно пользователь вводит:
1. текущий пароль
2. новый пароль
3. подтверждение нового пароля
Уязвимость
Нельзя доверять username, переданному клиентом, например: username=victim
Если username находится в hidden field и сервер доверяет ему, значение может быть изменено
Это может привести к:
- изменению пароля другого пользователя
- username enumeration
- brute-force паролей
