# Vulnerabilities in multi-factor authentication(Уязвимости в многофакторной аутентификации)
### MFA / 2FA - главное
- 2FA - ровно 2 разных фактора аутентификации
- Основные факторы:
  - Что ты знаешь - пароль, PIN
  - Что у тебя есть - телефон, токен, приложение с кодом
  - Что ты есть - биометрия
- 2FA безопаснее пароля, потому что злоумышленнику нужно получить сразу два разных фактора
- Безопасность 2FA зависит от реализации. Плохо реализованый 2FA можно обойти
- Два способа проверки одного фактора ≠ настоящая 2FA
  - Напрмер: пароль + код из email
  - Если доступ к email получается только с помощью пароля, то оба фактора фактически основаны на знании

# Two-factor authentication tokens(Токены двухфакторной аутентификации) 
### проверяющие коды пользователя обычно считываются с какого-либо устройства.
- Токены 2FA
  - Пример: RSA-токен, аппаратный токен, Google Authenticator
  - Такой способ безопаснее, когда код генерируется самим устройством, а не передается по сети\
- 2FA через SMS (SMS-коды тоже относятся к фактору "что у вас есть ", но имеют слабые места:
  - Перехват SMS -> злоумышленник может получить код
  - SIM-swap -> злоумышленник получает SIM-карту с номером жертвы и начинает получать ее SMS , включая коды 2FA

# Bypassing two-factor authentication(Обход двухфакторной аутентификации)
- Иногда 2FA реализована неправильно, поэтому её можно полностью обойти
- Типичная ошибка: после ввода пароля сервер уже считает пользователя авторизованным, хотя 2-й фактор ещё не пройден
- В таком случае защищённые страницы могут быть доступны без ввода кода 2FA

# Flawed two-factor verification logic(Недостатки логики двухфакторной аутентификации)
- После первого этапа сайт должен связать второй этап 2FA именно с той же учётной записью
- Уязвимость возникает, если сервер определяет аккаунт для второго этапа только по изменяемому параметру, например cookie account
- Если этот параметр можно изменить, можно попытаться подставить имя другого пользователя
- При отсутствии правильной проверки связи между этапами злоумышленник потенциально может пройти 2FA для чужого аккаунта, не зная его пароль
- Дополнительная проблема — если код 2FA можно эффективно подбирать перебором
