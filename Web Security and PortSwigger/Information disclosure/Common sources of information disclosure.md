# Common sources of information disclosure

##  распространенные примеры мест, где вы можете проверить, не была ли раскрыта конфиденциальная информация:
1. Files for web crawlers
2. Directory listings
3. Developer comments
4. Error messages
5. Debugging data
6. User account pages
7. Backup files
8. Insecure configuration
9. Version control history

### 1. Files for web crawlers
Многие веб-сайты предоставляют файлы /robots.txt, /sitemap.xmlпомогающие поисковым роботам ориентироваться на их сайте
Поскольку ссылки на эти файлы обычно не размещаются на сайте, они могут не сразу отобразиться в карте сайта Burp. Однако стоит попробовать перейти к ним вручную /robots.txtили /sitemap.xmlпоискать там что-нибудь полезное

### 2. Directory listings
Веб-серверы можно настроить на автоматическое отображение содержимого каталогов, в которых отсутствует индексная страница. Это может помочь злоумышленнику, позволяя ему быстро идентифицировать ресурсы по заданному пути и перейти непосредственно к их анализу и атаке
Однако, если веб-сайт также не обеспечивает надлежащий контроль доступа, утечка информации о существовании и местонахождении конфиденциальных ресурсов таким образом, безусловно, является проблемой

### 3. Developer comments
В процессе разработки в разметку иногда добавляются встроенные HTML-комментарии. Обычно эти комментарии удаляются перед развертыванием изменений в рабочей среде. Однако комментарии иногда могут быть забыты, пропущены или даже оставлены намеренно, поскольку кто-то не был полностью осведомлен о последствиях для безопасности
Иногда эти комментарии содержат информацию, полезную для злоумышленника. Например, они могут намекать на существование скрытых каталогов или содержать подсказки о логике работы приложения

### 4. Error messages
Содержимое сообщений об ошибках может раскрыть информацию о том, какой тип входных данных ожидается от данного параметра. Это может помочь сузить круг потенциальных целей атаки, выявив параметры, которые могут быть использованы злоумышленниками. Это даже может предотвратить трату времени на попытки внедрения вредоносных программ, которые просто не сработают
Подробные сообщения об ошибках также могут содержать информацию о различных технологиях, используемых веб-сайтом
Различия в сообщениях об ошибках также могут указывать на различное поведение приложения, происходящее за кулисами. Наблюдение за различиями в сообщениях об ошибках является важнейшим аспектом многих методов, таких как SQL-инъекции

### 5. Debugging data
Многие веб-сайты генерируют собственные сообщения об ошибках и журналы, содержащие большой объем информации о поведении приложения.
Отладочные сообщения иногда могут содержать важную информацию для разработки атаки:
1. Значения ключевых переменных сессии, которыми можно управлять с помощью пользовательского ввода.
2. Имена хостов и учетные данные для серверных компонентов
3. Имена файлов и каталогов на сервере
4. Ключи, используемые для шифрования данных, передаваемых через клиент
Отладочная информация иногда может записываться в отдельный файл, если злоумышленник получит доступ к этому файлу, он сможет использовать его в качестве полезного источника информации для понимания состояния приложения во время его выполнения
